def prepare_dataset(df):
    numeric_cols, categorical_cols = ml.split_feature_types(df)
    X_raw = df[numeric_cols + categorical_cols]
    y = df["class"]
    X_train_raw, X_test_raw, y_train, y_test = train_test_split(
        X_raw, y, test_size=0.2, stratify=y, random_state=RANDOM_STATE
    )
    pre = ml.make_onehot_preprocessor(numeric_cols, categorical_cols)
    X_train = pre.fit_transform(X_train_raw)
    X_test = pre.transform(X_test_raw)
    feature_names = pre.get_feature_names_out()
    y_train_bin = (y_train == "poisonous").astype(int).to_numpy()
    y_test_bin = (y_test == "poisonous").astype(int).to_numpy()
    return dict(X_train=X_train, X_test=X_test, y_train=y_train_bin, y_test=y_test_bin,
                X_test_raw=X_test_raw, feature_names=feature_names)

datasets = {
    "Classic": prepare_dataset(ml.load_classic()),
    "Secondary": prepare_dataset(ml.load_secondary()),
}

1. Human-readable rules from a shallow Decision Tree¶

Because our features are one-hot encoded, each split in the tree reads as a plain yes/no statement about a specific category (e.g. "does this mushroom have odor = foul?"), so a shallow tree's rules are directly interpretable — similar in spirit to the hand-derived logical rules in the original UCI documentation for the classic dataset.

for name, d in datasets.items():
    tree = DecisionTreeClassifier(max_depth=4, random_state=RANDOM_STATE)
    tree.fit(d["X_train"], d["y_train"])
    acc = tree.score(d["X_test"], d["y_test"])
    print(f"\n{'='*70}\n{name} dataset — shallow interpretable tree (depth=4, test accuracy={acc:.4f})\n{'='*70}")
    rules = export_text(tree, feature_names=list(d["feature_names"]), max_depth=4)
    # tidy the one-hot feature names for readability
    rules = rules.replace("num__", "").replace("cat__", "")
    print(rules)
    d["shallow_tree"] = tree

Reading these rules: a threshold like some-category <= 0.50 is really a yes/no test, since one-hot columns only take values 0 or 1 — <= 0.50 means "does not have this category", and > 0.50 means "has this category". For the classic dataset this should closely echo the "odor" and "spore-print-color" rules already found in the UCI documentation and in our Phase 2 feature-importance charts.

Notice the accuracy gap between the two shallow trees: the classic-dataset tree reaches ~99% accuracy at depth 4, while the secondary-dataset tree manages only ~71% at the same depth. This is a concrete, quantified version of the EDA/benchmarking finding that the secondary dataset has no single dominant feature like odor — a short, simple rule set just cannot capture it as well. The secondary dataset's full-depth tree (next section) still reaches ~99.9%, but needs many more splits combining weaker signals to get there.

2. Feature importance: Decision Tree vs. Random Forest vs. LightGBM¶

Do simple and complex models agree on what matters? Comparing importance rankings side by side is itself a form of explainability — if a fast, fully-grown Decision Tree and a 150-tree Random Forest broadly agree, that's reassuring; if they diverge, it's worth digging into why.

In [4]:
def top_importances(model, feature_names, n=10):
    imp = pd.Series(model.feature_importances_, index=feature_names)
    return imp.sort_values(ascending=False).head(n)

for name, d in datasets.items():
    full_tree = DecisionTreeClassifier(random_state=RANDOM_STATE)
    full_tree.fit(d["X_train"], d["y_train"])

    rf = RandomForestClassifier(n_estimators=150, random_state=RANDOM_STATE, n_jobs=-1)
    rf.fit(d["X_train"], d["y_train"])

    lgbm = LGBMClassifier(n_estimators=200, random_state=RANDOM_STATE, n_jobs=-1, verbose=-1)
    lgbm.fit(d["X_train"], d["y_train"])

    d["full_tree"], d["rf"], d["lgbm"] = full_tree, rf, lgbm

    fig, axes = plt.subplots(1, 3, figsize=(16, 5.5))
    for ax, (mname, model) in zip(axes, [("Decision Tree", full_tree), ("Random Forest", rf), ("LightGBM", lgbm)]):
        top = top_importances(model, d["feature_names"])
        top.iloc[::-1].plot.barh(ax=ax, color="#55A868")
        ax.set_title(f"{name}: {mname}")
    plt.tight_layout()
    plt.show()

3. SHAP: global feature impact¶

SHAP values quantify each feature's contribution to individual predictions, then aggregate into a global importance measure — computed here on the LightGBM model for each dataset, on a 300-row sample of the held-out test set for speed.

In [5]:
shap_samples = {}
for name, d in datasets.items():
    X_te_dense = d["X_test"][:300].toarray() if hasattr(d["X_test"], "toarray") else d["X_test"][:300]
    explainer = shap.TreeExplainer(d["lgbm"])
    sv = explainer(X_te_dense)
    sv.feature_names = [f.replace("num__", "").replace("cat__", "") for f in d["feature_names"]]
    shap_samples[name] = sv

    plt.figure()
    shap.plots.bar(sv, max_display=12, show=False)
    plt.title(f"{name} dataset — global SHAP feature importance")
    plt.tight_layout()
    plt.show()

4. SHAP: explaining individual predictions¶

"Why did the model classify this specific mushroom as poisonous?" — a waterfall plot shows exactly which features pushed the prediction up (toward poisonous) or down (toward edible) for one example from each dataset.

In [6]:
for name, d in datasets.items():
    X_te_dense = d["X_test"][:300].toarray() if hasattr(d["X_test"], "toarray") else d["X_test"][:300]
    y_te_sample = d["y_test"][:300]
    preds = d["lgbm"].predict(X_te_dense)

    # pick a correctly predicted poisonous example
    candidates = np.where((preds == 1) & (y_te_sample == 1))[0]
    idx = candidates[0]

    plt.figure()
    shap.plots.waterfall(shap_samples[name][idx], max_display=12, show=False)
    plt.title(f"{name} dataset — why was mushroom #{idx} predicted poisonous?")
    plt.tight_layout()
    plt.show()

5. Tying explainability back to the EDA and benchmarking findings¶

  • Classic dataset: every method here — the shallow tree's rules, the DT/RF/LightGBM importance rankings, and the SHAP values — converge on the same story as Phase 1's EDA and Phase 2's model coefficients: odor is overwhelmingly the dominant signal, with spore-print-color and gill-color as secondary contributors. A model trained on this dataset is, in effect, learning a close approximation of the hand-derived rules already published in the original UCI documentation.
  • Secondary dataset: with no odor field, explanations are more distributed — stem-width, stem-color, cap-diameter, and several ring/spore-print categories share the load. No single feature dominates a SHAP plot the way odor dominates the classic dataset's, which is consistent with Phase 2/3's finding that this dataset needs models capable of combining multiple moderate signals rather than one near-deterministic rule.
  • Practical framing for a "why" answer: for any individual mushroom, the SHAP waterfall plot above is a template for a plain-language explanation — e.g. "predicted poisonous mainly because of its odor category and spore-print color" (classic) or "predicted poisonous mainly because of its stem width and stem color, with smaller contributions from cap diameter and ring type" (secondary).

Standing caveat, restated: these are statistical patterns in two benchmark datasets, one of which is entirely simulated. Neither the models nor these explanations should be used to judge whether any real mushroom is safe to eat.
